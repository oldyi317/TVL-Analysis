# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

一般 TVL 球迷，手機閱讀為主。典型情境是賽後或賽中拿起手機查戰績與自己支持的球隊、球員的數據；要在幾秒內找到自己的隊。

次要讀者（未確認、不特別設計）：教練、球員、媒體。

## Product Purpose

把每日爬蟲累積的 TVL 企業排球聯賽資料（賽季、球隊、賽事、週登錄、單場數據）整理成一般球迷在手機上好讀的靜態網站。成功 = 球迷打開就能找到當季、自己的組別與球隊，資料與官網一致且每日更新。

本站取代舊的 Streamlit 儀表板（ADR-0001）。第一期（Issue #5）打通「資料庫 → JSON → 靜態頁 → GitHub Pages」，第二期頁面已全部上線（見 Capabilities）。

## Positioning

官網只有單場資料；本站把所有場次串起來，做出跨場次累積的球員與球隊數據（PR 值、趨勢、戰績）與賽前勝率。這是官網拿不到的東西。

## Operating Context

- 資料來源：TVL 官網與外部統計系統，每日 GitHub Actions 爬蟲寫入 SQLite 並 commit。
- 建置時由 Python 匯出器產 JSON，前端只讀 JSON；沒有執行期 API、沒有登入、沒有使用者輸入。
- 部署在 GitHub Pages 子路徑 `/TVL-Analysis/`，每次 push main 重建。
- 網址結構 `/<賽季>/<組別>/...`，組別值為 men、women；根路徑導向當季，組別取本機記住的上次選擇（讀不到就男子組）；每頁頂部可切換賽季與組別並停留在同一頁面類型，從單場、球隊、球員頁切換則退回對應列表。
- 當季 = seasons.json 的 current_cup_id（匯出器以 cup_id 最大者判定）。
- 開季初期官網資料未齊、新隊名可能非定稿；球隊身分以 DB 的 teams / team_aliases 為準。

## Capabilities and Constraints

- 已上線頁面：首頁（最新比分、戰績摘要、下一場含賽前勝率）、賽事列表（可依月份跳轉）、單場頁（逐局比分、單場數據）、戰績（依官方規則排序）、球隊列表、球隊頁（隊徽、當季戰績、賽事清單、當週登錄或賽季報名名單）、球員列表、球員頁（基本資料、三大項、進階數據、逐場趨勢）、`/styleguide/` 簽核頁。
- 圖表用 ECharts（`src/lib/chart/Chart.svelte`）。
- 球隊身分唯一來源是 DB 的 teams 表：short_name、color（hex）、is_active。非現役球隊顯示在該季戰績與列表，但不給球隊頁（ADR-0002）。
- 男女組 team_id 會重複，識別一律用 (team_id, group)。
- 進階數據：九項比率（攻擊成功率、接發球到位率、發球得分率、防守到位率、場均得分、舉球到位率、每局攔網、防守負荷、防守效率）；PR 值為同組別、同主要位置球員中的百分等級，門檻 5 局，涵蓋七項（不含場均得分與防守負荷）。
- 賽前勝率由爬蟲端模型計算寫入 DB（ADR-0003），只對未開打賽事顯示；賽季報名名單只補顯示、不進比較（ADR-0004）。
- 每週登錄名單會變動，名單外球員資料可能缺背號與位置；介面對缺值要防禦。
- 資料品質原則：只標記與警告異常，不插補、不竄改原始數據。
- 用詞依 repo 根目錄 `CONTEXT.md` 詞彙表：用「組別、賽季、賽事、戰績、週登錄、單場數據、進階數據、PR 值、賽前勝率、黃金決勝局、隊徽」；不用「性別、gender、cup、盃、roster、Box Score、預測、standing、logo」等 Avoid 詞。
- 全站繁體中文。

## Brand Commitments

- 站名「TVL 數據」，頁首固定附「非官方・資料整理自聯賽官網」。
- 必須註明非官方：資料整理自官網，非聯賽官方網站。
- 隊徽可用於全站（球隊頁、球隊列表、賽事卡、戰績表等）；來源 `web/static/logos/`（原圖 `assets/team_logo/`），每支現役隊都要有隊徽（`docs/ops/season-switch.md`）。聯賽官方 logo 不使用。
- 2026-10-20 使用者釘定的視覺約束：整站替換視覺世界並建立 DESIGN.md，以參考截圖 `web/.impeccable/reference/redesign-2026-10-reference.png`（運動即時比分 dashboard）為釘定的美學參考。釘的是美學（卡片、配色、圓角、圖表風格），不是其資訊架構：手機優先不變，截圖中的桌面 sidebar 不改變手機導覽結構。

## Evidence on Hand

- 真實資料：`data/db/tvl_database.db`（2024-25、2025-26 兩個完整賽季加 2026-27 開季中，逐場球員統計），由匯出器產成 `web/src/lib/data/*.json`（不進 git）。
- 圖像資產只有隊徽與 favicon；沒有球員照片、場館照片、插畫；不得自行生成或暗示有這些素材。
- 沒有使用者見證、流量數據、媒體報導；不得編造。

## Product Principles

1. 手機優先：單手、豎屏、光線不佳的看台或客廳是主要場景。
2. 找得到比看得美重要：賽季、組別、球隊三層導航每頁可見。
3. 資料忠實：顯示值與 DB 一致，缺值就顯示缺值，不猜。
4. 靜態與可預測：所有頁面建置時產生，URL 可分享、可書籤。
5. 用詞一致：介面文案遵守詞彙表，不混用同義詞。

## Accessibility & Inclusion

- 隊色僅作輔助識別，任何靠顏色區分的地方都要有文字（簡稱）。
- 圓形隊標上的文字需達可讀對比；隊色由 DB 給定、不可改，對比不足時用文字描邊或底色處理而非換色。
- 現有實作已支援深色模式與 prefers-reduced-motion，重設計須維持。
